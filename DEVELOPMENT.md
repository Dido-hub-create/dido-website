# DIDO v0.4

[Управление на видеа, социално споделяне и начална страница от телефон](docs/DIDO-v0.4.md). Публичният адрес и YouTube каналът са празни по подразбиране и се попълват през Pages CMS. Преди натискане върху видео не се зарежда iframe; социалните изображения се генерират локално при build като 1200 × 630 JPEG с целия кадър. Няма YouTube Data API или автоматично публикуване във Facebook.

Инструкции за собственика от телефон, точните Cloudflare Pages настройки и безопасният преход от `feat/dido-v0-1` към `main` са в [docs/CLOUDFLARE-PAGES-BG.md](docs/CLOUDFLARE-PAGES-BG.md). След еднократното свързване ежедневните редакции се правят в Pages CMS → `main` и се публикуват автоматично, без терминал или Codespaces. До финалното сливане CMS остава върху работния клон; не натискай Cloudflare **Save and Deploy** предварително.

Статичен сайт с Astro, локално хостван шрифт Manrope и чист CSS. Не използва база данни, платени API или сървърен абонамент. Оригиналният README, пробната публикация и четирите оригинални снимки са запазени.

## Локална работа

Необходим е Node.js 24 (проверено с 24.22.1; версията е в `.nvmrc`).

```sh
npm ci
npm run dev
```

Отвори адреса, отпечатан от Astro. За статичен build и преглед:

```sh
npm run verify
npm run preview
```

`npm run verify` изпълнява Astro/TypeScript проверка, production build и автоматичните тестове. Тестовете обхващат оригиналната публикация, съществуването на локалните връзки и изображения, съвместимостта със стари данни, чернови, липсващи снимки и къси описания. Изолиран временен проект проверява допълнителни публикации; реалните публикации не се променят. GitHub Actions изпълнява същите проверки, без deployment.

## Страници

- `/` — Начало, последни публикации, лични рекорди и планирани приложения.
- `/byagane/` — Бягане, рекорди и филтри по тема.
- `/tehnologii/` — Технологии, моите приложения и филтри по тема.
- `/polezno/` — Полезно; тук попадат и старите публикации без категория.
- `/za-men/` — За мен, място за портрет, биография и контакти.
- `/finansi/` — Финанси и Bitcoin, без външни API.
- `/posts/<име-на-файла>/` — всяка публикувана статия.
- `/404.html` — страница за несъществуващ адрес.

## Редактиране с Pages CMS

Отвори [Pages CMS](https://app.pagescms.org/), влез с GitHub и избери `Dido-hub-create/dido-website`. След преглед и сливане на Pull Request избери `main`. За преглед преди сливането можеш да избереш работния branch в CMS, ако интерфейсът го предлага.

В „Настройки на сайта“ вече се управляват и името, подзаглавието, незадължителното изображение за лого и шестте надписа на главното меню. Адресите са фиксирани. Новите записи получават автоматично безопасни имена; неправилно именуван файл се пропуска с диагностика, вместо да блокира целия build. GPX името се генерира от заглавието и се записва безопасно и вътре в XML; геометрията и разрешенията остават същите.

### Публикации

1. Отвори „Публикации“ → съществуваща публикация или нов запис.
2. Попълни заглавие и съдържание. Избери раздел и по желание тема, дата и кратко описание.
3. Основната снимка се избира от „Основна снимка“. „Галерия“ запазва качването на до 10 снимки. Снимки между абзаците се добавят през редактора на съдържанието.
4. Избери „Публикувано“ и запази. „Чернова“ изключва статията от build, включително директния ѝ адрес.
5. След бъдещото свързване с Cloudflare Pages записът в production branch стартира автоматичен build. Промяната става видима само след успешното му приключване.

Новите полета не са задължителни. Съществуващите `title`, `cover`, `gallery`, `body`, media пътища и Markdown редактор са запазени. Публикация без статус е публикувана, без категория се показва в „Полезно“, без дата не показва измислена дата. Описание се извлича от текста, ако не е зададено. Празни снимки и липсващи локални основни снимки/галерии се пропускат. Относителните CMS пътища `public/images/...` и `images/...` се нормализират за основната снимка и галерията; Markdown изображенията трябва да използват `/images/...`, както ги записва текущата CMS конфигурация.

За да запазиш адреса на статията, не преименувай Markdown файла. Сайтът чете всички `.md` файлове от `src/content/posts`, включително подпапки. Редът е по зададена дата, а при липса — по име на файл. Публикациите с `draft: true` също остават скрити за съвместимост.

### Представяне и снимки на сайта

В „Настройки на сайта“ редактирай текста на началната страница, голямата снимка, краткото представяне, биографията, личния портрет, контактите и личните рекорди. Биографията е обикновен текст с нови редове. Контактите и портретът са празни по подразбиране; добави реални данни, когато решиш. За контактна връзка използвай пълен `https://` адрес. Няма външни връзки към непубликуваните приложения.

## Публикуване в Cloudflare Pages — само след одобрение

Проектът **не е публикуван** и не е създаван Cloudflare проект. След одобрение:

1. Прегледай Pull Request и го слей в `main`, когато си готов.
2. В Cloudflare отвори Workers & Pages → Create → Pages → Connect to Git (наименованията може да се променят).
3. Избери GitHub хранилището `Dido-hub-create/dido-website` и production branch `main`.
4. Задай следните настройки:

| Настройка | Стойност |
| --- | --- |
| Framework preset | Astro |
| Root directory | коренът на хранилището (празно) |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Environment variable | `NODE_VERSION=24.22.1` |
| Environment variable (по желание) | `ASTRO_TELEMETRY_DISABLED=1` |
| Production branch | `main` |

5. Избери безплатния план. Използвай предоставения `*.pages.dev` адрес — собствен домейн не е необходим.
6. Стартирай първото публикуване и провери build логовете. Не са необходими Astro адаптер, Workers runtime, D1/R2, API ключове или `wrangler.toml`.
7. В Git интеграцията остави автоматично изграждане при промени в `main`. Pages CMS прави Git commit; Cloudflare изгражда наново всички статични страници, а успешно публикуваната версия заменя предишната. При неуспешен build предишната версия остава активна.
8. Задай **Preview deployments: None**. Preview за други branches може да се включи отделно след изрично решение за достъпните preview адреси.

Cloudflare Pages има безплатни квоти за изграждания и файлове. Не активирай платен план. Проектът не съдържа автоматичен deployment workflow и не изисква закупуване на домейн.

## Структура за разработчици

- `.pages.yml` — съвместимата CMS конфигурация и новите незадължителни полета.
- `src/content/posts/` — оригинални и бъдещи Markdown публикации.
- `src/content.config.ts` — schema с поддръжка на празни/липсващи метаданни.
- `src/data/site.json` — редактирано от CMS представяне на сайта.
- `src/lib/` — категории, филтриране, нормализиране на снимки, извличане на описания.
- `src/components/` и `src/layouts/` — общи елементи, меню, карти, галерия и колонтитул.
- `src/styles/global.css` — цветови променливи, типография и responsive стилове.
- `tests/` — автоматични проверки с вградения Node.js test runner.

Личният рекорд `2:07:14` е единственият предварително зададен резултат. Останалите дистанции са „Предстои“. Рекордите се редактират през „Настройки на сайта“ → „Лични рекорди“ в Pages CMS. Остави полето празно, докато имаш потвърден резултат.

## Одобрен визуален ориентир и преглед без локален Node.js

Композицията на началната страница е обновена според предоставения визуален дизайн. Подробното сравнение и съзнателните разлики при непотвърдени данни са в [docs/DESIGN-REVIEW.md](docs/DESIGN-REVIEW.md). Допълнителните изображения до рекордите, Финанси и За мен могат да се сменят през Pages CMS.

За частен преглед през браузъра е подготвена конфигурация за GitHub Codespaces: [docs/ONLINE-PREVIEW.md](docs/ONLINE-PREVIEW.md). Workflow-ът за проверки запазва и готов статичен build като artifact за 7 дни. Нито тази конфигурация, нито artifact-ът публикуват сайта автоматично.

## DIDO v0.2

Добавени са състезания, архив, маршрути с обработка на GPX, Leaflet карти, отделни разрешения за карта/изтегляне и общи CMS настройки за кадриране. Подробните инструкции, ограниченията на публичното GitHub хранилище, условията на картографската услуга и проверките са в [docs/DIDO-v0.2.md](docs/DIDO-v0.2.md). **Прочети раздела за публичността на оригиналните GPX файлове преди първото качване.**

Новите секции са `/byagane/marshruti/` и `/byagane/sastezaniya/`. Данните за маршрути и състезания се записват от CMS като JSON в `src/content/routes` и `src/content/races`; изходните GPX са в `src/data/gpx`, извън `public/`. `npm run cms:check` проверява YAML структурата, типовете полета, компонентите и връзките; `npm run verify` включва и тази проверка.
