## Настройки през Pages CMS

В **Настройки на сайта** са добавени пет незадължителни полета:

| Поле | Поведение |
| --- | --- |
| `siteTitle` — Заглавие на сайта | Празно = досегашното „Име на сайта“ (`siteName`). Попълненото заглавие се използва за името/метаданните и текстовия fallback. Самият SVG надпис остава Dido. |
| `headerLogoAlt` — Алтернативен текст | Празно = името на сайта; използва се от екранни четци. |
| `useImageLogo` — Използвай графичното лого | По подразбиране включено; изключването връща текстовото лого с линията. |
| `headerLogoWidthDesktop` | По подразбиране 128 px, диапазон 96–160 px. При по-тесен desktop хедър се ограничава до 128 px, за да остане място за менюто. |
| `headerLogoWidthMobile` | По подразбиране 108 px, диапазон 88–128 px; важи и за таблет с мобилно меню. |

Съществуващото поле **Собствено лого** (`logoImage`) продължава да работи. Празно поле използва вграденото Dido с бегач. Ако изрично избраният локален файл липсва или е невалиден, build-ът показва текста. Ако изображение не се зареди в браузъра, JavaScript също го заменя с текста. Изключеното `useImageLogo` не изисква файл. Долната идентичност използва същия избор, с компактна ширина до 112 px.

Незадължителните полета може да липсват след CMS запис — нормализиращият слой предоставя стойностите по подразбиране само в паметта. Действителният `site.json` не е редактиран от тази промяна. Не е необходимо ръчно добавяне на JSON ключове.

## Какво да разгледа собственикът

1. Логото и бегачът в хедъра на телефон и компютър; клик върху логото от друга страница трябва да връща началната.
2. Мобилното меню на 320/390/768 px и пълното меню на 1440 px. Хедърът трябва да запази височината си и да няма хоризонтален скрол.
3. Favicon при светла/тъмна системна тема и в нов частен прозорец, ако браузърът показва кеширана икона.
4. След евентуално сливане: CMS включване/изключване и желаните ширини. За преглед преди сливане не записвай тези настройки в production `main`; използвай само новия работен branch.

Публикациите, видеата, галериите, снимките, рекордите, състезанията, GPX оригиналите и обработката им не са редактирани. Новите автоматични тестове покриват векторните assets, иконите, CMS стойностите и fallback поведението. Визуалният преглед се прави с Chromium на 320/390/768/1440 px, отделно от unit/build проверките. GitHub Actions запазва готовия сайт като artifact `dido-static-preview`; това не променя production сайта. Ако Cloudflare не създаде branch preview автоматично, използвай приложеното визуално preview и artifact-а — production deployment не се стартира за тази цел.
