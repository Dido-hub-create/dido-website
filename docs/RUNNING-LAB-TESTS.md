# Running Lab — проверки и действителни екрани

Последната компактна подредба и GPS следването имат собствен [отчет с измервания и screenshots](RUNNING-LAB-COMPACT.md). Числата в следващите раздели са от предишните етапи.

Актуалното надграждане на едновременния изглед карта/графики е описано в [RUNNING-LAB-WORKSPACE.md](RUNNING-LAB-WORKSPACE.md). Следващите числови отчети са запазени за предишните версии.

Картографското надграждане има собствен актуален [отчет, методика и screenshots](RUNNING-LAB-MAP.md): `verify` — 118 успешни и 21 browser сценария, изпълнени отделно и успешни; CI без външните файлове — 116 успешни и 23 опционални пропуска. Следващите секции пазят подробностите за предишното визуално надграждане.

Проверено на 16.11.2026 с Node 24.22.1, Astro 7.4.7 и Chromium. Основата включва актуалния `main` и новите редакции през Pages CMS; няма промяна в съдържанието, реалните рекорди, съществуващите снимки/маршрути, `.pages.yml`, Analytics или GPS разрешенията.

## Автоматични проверки

- `npm run verify`: CMS валидатор, Astro/TypeScript (0 errors/warnings/hints), production build (29 статични страници), Node тестове.
- В локалната пълна проверка са включени и външните публични FIT/TCX fixtures чрез посочените по-долу променливи. След визуалното надграждане: 130 общо, 112 успешни, 0 неуспешни и 18 браузърни сценария, пропуснати в Node командата и изпълнени отделно. Финалният CI статус е в GitHub Actions/PR.
- Без опционалните външни файлове обичайният CI изпълнява 110 теста и пропуска 20: 18 браузърни и 2 външни corpus проверки. Това не се представя като проверка на браузърите в GitHub Actions.
- Браузърният набор включва **13 съществуващи регресии**, **3 първоначални Lab сценария** и **2 нови визуални Lab сценария**. Новата методика и действителните екрани са в [RUNNING-LAB-VISUAL.md](RUNNING-LAB-VISUAL.md).

Старите unit/browser проверки за лични рекорди са направени устойчиви спрямо текущите CMS записи: optional metadata fixture вече изрично пропуска полетата, а baseline проверява действително въведените места/дати. Първоначално тези тестове предполагаха, че собственикът няма въведени дати. Реалните времена/места/дати в `site.json` не са променяни.

Допълнително са внесени реалните GPX/TCX/FIT примери в браузър, създадени са три PDF отчета (анализ, сравнение, рекорди), а с `pdftotext` е потвърден четимият текст на кирилица. Картата е изключена от печатния отчет по подразбиране. При мрежовия тест външният analytics script е блокиран; тестът доказва липса на **нови Lab заявки/пакети с тренировки**, не че съществуващият Cloudflare Web Analytics няма свой стандартен трафик в production.

При визуалното надграждане всички 18 браузърни сценария са успешни. Първото паралелно регресионно изпълнение, едновременно с тежките fixture builds, достигна 90 s timeout на стария анализатор и хвана преходно `animationName: none` след смяна на reduced-motion в кабинета. Двата сценария са повторени последователно: съответно ~37,8 s и ~25,0 s, без грешки и без промяна на приложенията или тестовете им. Новите визуални сценарии преминаха заедно; след изчистване на артефакт от извънекранния skip-link при голям screenshot дългият сценарий е повторен успешно (~27,4 s). Самият skip-link и клавиатурното му поведение не са променяни. Допълнително е прегледана реалната публична Кайлъка в новата локална GPS схема при 1440/390 px, с маркери и избран диапазон 5–10 км.

## Възпроизводими команди

Обичайно:

```sh
npm ci
ASTRO_TELEMETRY_DISABLED=1 npm run verify
```

Опционални реални corpus проверки (клониране само в игнорирания `work/`, без изпълнение на външен код):

```sh
git clone https://github.com/jimmykane/fit-parser.git work/fit-parser-audit
git -C work/fit-parser-audit checkout 9f4958b9493b1eb13d68940eebc8d56d3598db2b
git clone https://github.com/vkurup/python-tcxparser.git work/tcx-parser-audit
git -C work/tcx-parser-audit checkout 9640e01639f5602107a485db5de9a4ea0309ae9f
DIDO_LAB_EXTERNAL_FIT_DIR="$PWD/work/fit-parser-audit" \
DIDO_LAB_EXTERNAL_TCX_DIR="$PWD/work/tcx-parser-audit/tests/files" \
node --test tests/lab-real-files.test.mjs
```

За браузърните тестове използвай инсталиран Playwright модул/Chromium и локален `npm run preview` след build. Няма нова production или dev зависимост от Playwright:

```sh
DIDO_BROWSER_MODULE=/absolute/path/to/playwright/index.js \
DIDO_BROWSER_URL=http://localhost:4321 \
node --test --test-concurrency=2 tests/*browser.test.mjs
```

Прогресът, отказаната квота и cancel се проверяват с действителен Worker/IndexedDB, а не чрез замяна на цялата библиотека с mock. Графиките/PDF се генерират от внесените данни. 4× CPU throttling е Chrome емулация, не физически телефон; реални iOS/Safari и конкретните часовници остават приемателна проверка.

## Производителност и ограничения

На тази машина 200 малки GPX (~10 200 точки) се внасят за 7,76–9,91 s. FIT с 10 000 точки при 4× CPU throttling — 1,49–1,97 s. Контролният аналитичен benchmark със 100 000 точки и 29 дистанции е ~6,37 s; преди оптимизацията е ~15,44 s. Интерфейсният heartbeat продължава по време на Worker обработката. Новият лимит обхваща и sessions в многосесийни TCX/FIT, не само броя файлове.

Последният измерен build има Worker ~117 kB / ~40 kB gzip и отделен FIT decoder ~295 kB / ~61 kB gzip. Файловите имена/размери могат да се променят при build. Кодеците са локални, мързеливи и не се товарят на началната страница. Не се обещава неограничена библиотека или еднакво време на всеки телефон.
